From the first mount to the next update

1. Create the root and describe the first screen

AEM serves an HTML container. The script calls createRoot on that container and root.render with a React element describing the counter and the log. A React element is a JavaScript description of what to show. JSX is one way to write that description. It contains a type, props and children. These descriptions are often called the virtual DOM.

React calls the counter with its label and trace props. On this first mount, useState(0) initializes value to 0 and returns a setter. useRef(null) creates a stable object whose current will later hold the output node. The counter returns an element tree for its label, output and button.

2. Reconcile and commit the initial screen

During the render phase, React reconciles the element descriptions with its internal Fiber tree. A Fiber tracks a piece of the mounted UI, its state and pending work. On the first mount there is no previous counter subtree to reuse. React prepares the corresponding browser DOM nodes. Render work can be interrupted, restarted or discarded before it is committed, so the component function should stay pure.

During the commit, React inserts the nodes into the container and attaches the DOM ref. useLayoutEffect can now read the actual 0 before the browser paints the committed update. useEffect runs after the commit. Depending on scheduling, it may run before or after the browser has painted.

3. Click and queue a state update

The browser dispatches a click and React calls the handler associated with the button. That handler sees the state snapshot from the render that created it, so the first click sees value = 0. Calling setValue(previous => previous + 1) queues an updater. It does not overwrite the local value in that handler. React can batch updates and applies functional updaters in order to the pending state.

4. Render again and determine what changes

When React processes the update, the updater produces 1 and React calls the counter again with that state. The incoming props stay the same. If the counter passed value to a child, the child would receive it as a new prop on that render. The counter now describes an <output>1</output> in the same position as the previous output. React matches children by type and position or key as applicable. It can preserve the output node and update its text.

5. Commit, run effects and give the browser a chance to paint

React commits the text change to the real DOM. The layout effect reads 1 and compares the current DOM reference with the previous one. The ordinary effect then runs for the committed value. The browser can recalculate styles and layout as needed, paint, and composite what appears on screen. A requestAnimationFrame callback runs before a repaint. The next callback indicates a frame opportunity, without measuring whether the pixels were actually painted.

How to read the event log

Click and Update requested are recorded in the handler. Render result and React element describe the render that reached the commit. Commit / DOM records the actual DOM text and whether the node was reused. The effects and frame callbacks add their own entries. The log subscribes separately from the counter, so recording an entry does not update the counter’s state. The timestamps show observations in this demo. React’s individual Fiber comparisons and discarded render attempts are internal and are not recorded here.
